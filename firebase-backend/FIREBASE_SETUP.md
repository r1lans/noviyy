# Настройка Firebase (аккаунты учеников + база данных сайта)

Один раз, минут 15-20. После этого сайт сам подключится.

## Шаг 1 — создайте проект

1. Откройте console.firebase.google.com → «Add project» / «Добавить проект».
2. Назовите его, например, `thestarth`. Google Analytics можно отключить
   (не нужен для наших задач).

## Шаг 2 — включите вход по email/паролю

1. В меню слева: Build → Authentication → Get started.
2. Вкладка «Sign-in method» → «Email/Password» → включить (Enable) → Save.

## Шаг 3 — создайте базу данных

1. В меню слева: Build → Firestore Database → Create database.
2. Выберите «Start in production mode» (это важно для безопасности).
3. Регион — любой ближайший (например Europe-west, Asia-south).

## Шаг 4 — настройте правила доступа

1. В Firestore Database → вкладка «Rules».
2. Замените всё содержимое на файл `firestore.rules`, который я прислал
   рядом с этой инструкцией → Publish.

Эти правила уже настроены так, что:
- каждый ученик видит и редактирует только свой профиль
- новости/отзывы читают все, но пишет только админ (посетитель может лишь
  отправить отзыв «на проверку» — он не виден, пока админ его не опубликует)
- учителей (`teachers`) и результаты (`results`) читают все, а добавляет,
  меняет и удаляет только админ — из вкладок «Учителя» и «Результаты»
- настройки сайта редактирует только админ

> **Если вы обновляете сайт с прошлой версии:** обязательно заново вставьте
> содержимое `firestore.rules` во вкладку Rules и нажмите Publish. Без этого
> вкладки «Учителя» и «Результаты» в админ-панели не смогут ничего сохранить
> (будет ошибка «Missing or insufficient permissions»).

## Шаг 5 — получите конфигурацию для сайта

1. Шестерёнка рядом с «Project Overview» → Project settings.
2. Внизу вкладки «General» → «Your apps» → иконка `</>` (Web).
3. Назовите приложение (например `thestarth-web`) → Register app.
4. Появится блок кода `const firebaseConfig = {...}` — скопируйте только
   этот объект.
5. Откройте файл `firebase-config.js` в проекте сайта и вставьте
   скопированные значения вместо пустых строк.

## Шаг 6 — назначьте себя админом

Это делается только ПОСЛЕ того, как вы хотя бы раз зарегистрируетесь на
самом сайте через обычную форму (кнопка «Войти» → «Регистрация»).

1. Зарегистрируйтесь на сайте своим email.
2. В консоли Firebase: Authentication → Users → найдите свой email →
   скопируйте его **User UID** (длинная строка справа).
3. Firestore Database → Data → «Start collection» → имя коллекции:
   `admins`.
4. Document ID: вставьте скопированный UID. Добавьте любое поле,
   например `role` (string) = `admin` → Save.
5. Теперь при входе в `admin.html` под этим аккаунтом откроется панель
   администратора.

Чтобы добавить второго админа — повторите шаги 2-4 для другого аккаунта,
**или** проще: как только у вас есть первый админ, дальше можно назначать
и админов, и преподавателей прямо из панели (см. ниже) — вручную лезть в
консоль Firebase нужно только один раз, для самого первого админа.

## Роли: преподаватель и админ — прямо из панели

В `admin.html`, вкладка «Ученики», у каждого зарегистрированного
аккаунта есть выпадающий список «Роль»: Ученик / Преподаватель /
Администратор.

- **Преподаватель** — этот человек появится в списке преподавателей на
  вкладке «Расписание» (группа «Преподаватели-аккаунты»), и в своём
  личном кабинете увидит раздел «Расписание (как преподаватель)» со
  своими уроками и кнопкой входа в видеозвонок.
- **Администратор** — сразу получает доступ к `admin.html`, без
  повторения шагов из консоли Firebase.

Учтите: любой админ может назначить админом кого угодно через эту
панель — так что права админа стоит давать только людям, которым вы
доверяете.

## Шаг 7 — расписание: ссылка для каждого преподавателя

У каждого преподавателя своя страница расписания, доступная по прямой
ссылке (без пароля — это осознанное упрощение для такого масштаба):

- `.../teacher-schedule.html?id=firdavs`
- `.../teacher-schedule.html?id=sadokat`
- `.../teacher-schedule.html?id=javokhir`
- `.../teacher-schedule.html?id=behruz`
- `.../teacher-schedule.html?id=azizbek`

Отправьте каждому преподавателю его ссылку в Telegram один раз — дальше
это просто закладка в браузере, куда он заходит и видит свои уроки на
сегодня с кнопкой входа. Расписание добавляет админ через `admin.html`
(вкладка «Расписание»).

### Важно про индекс Firestore
Отзывы, новости, результаты, учителя и расписание теперь сортируются прямо
в браузере, поэтому для них индексы создавать **не нужно** (раньше из-за
этого одобренные отзывы могли не показываться). Если ошибка про индекс всё же
появится в другом месте — подход ниже. Расписание использовало несколько разных запросов (расписание ученика,
расписание преподавателя по ссылке, расписание преподавателя-аккаунта
через роль) — при первом использовании **каждого** из них в консоли
браузера может появиться ошибка вида `The query requires an index` со
ссылкой. Это нормально — просто переходите по ссылке, нажимайте «Create
Index», ждите 1-2 минуты и обновляйте страницу. Может понадобиться
сделать это 2-3 раза при первом запуске, дальше это разовая настройка,
которая больше не появится.

## Готово

Больше ничего вручную создавать не нужно — коллекции `users`, `news`,
`reviews`, `nicknames`, `settings`, `teachers`, `results` сайт создаст сам
при первом использовании.

## Учителя и результаты — как пользоваться

- **Админ-панель → «Учителя».** В первый раз нажмите «Подключить управление
  учителями» — 5 текущих преподавателей перенесутся в базу (или просто
  добавьте нового — перенос предложится сам). Дальше можно менять, удалять и
  добавлять учителей; они сразу меняются на странице «О нас».
  Фото загружается прямо с компьютера и сжимается автоматически.
- **Админ-панель → «Результаты».** Загрузите фото сертификата, впишите общий
  балл и баллы по частям — карточка появится на странице «Результаты». Там
  при наведении курсора сертификат увеличивается лупой (на телефоне —
  нажатие открывает крупное фото).
- **Отзывы.** Готовых отзывов в коде больше нет: на сайте показываются
  только те, что посетитель оставил через форму, а вы опубликовали во
  вкладке «Отзывы».

### Важно
- `firebaseConfig` (Шаг 5) — это НЕ секретный ключ, его можно спокойно
  оставлять в коде сайта, так задумано самим Firebase. Реальная защита
  данных — в правилах доступа (Шаг 4), а не в том, что конфиг скрыт.
- Оплата (Payme/Click) и заявки на оплату по-прежнему идут в Google
  Таблицу, как настроено раньше — это не меняется.

## Переводы и Google Таблица (новое)

- **Автоперевод.** Когда админ добавляет/меняет учителя, публикует отзыв или
  добавляет новость, тексты сами переводятся на русский, узбекский и
  английский (бесплатный сервис MyMemory, прямо из браузера админа) и
  сохраняются вместе с оригиналом. Посетители видят текст на своём языке.
  Для уже существующих отзывов и новостей есть кнопки «Перевести …» во
  вкладках. У сервиса есть дневной лимит — если он исчерпан, сайт покажет
  текст на исходном языке, а перевод можно повторить позже.
- **Google Таблица.** Каждая регистрация записывается в таблицу одновременно с
  Firebase. Адрес таблицы вставляется один раз в `sheets-config.js`, подробнее —
  `sheets-logging/SETUP.md`.
- **Правила базы** обновлять не нужно (новые поля хранятся внутри
  существующих документов `teachers`, `reviews`, `news`).

## Видео на главной (карусель) — одноразовая настройка

Админ добавляет видео во вкладке «Видео» в `admin.html`. Чтобы это заработало:

1. **Правила Firestore.** Firestore Database → Rules → вставьте обновлённый
   `firestore.rules` из этой папки (в нём появился блок `heroVideos`) → Publish.
2. **Firebase Storage** (там лежат сами видеофайлы). В консоли: Build → Storage →
   Get started. Firebase может попросить перейти на тариф Blaze (оплата по факту,
   есть бесплатная квота) — если не хотите, пропустите этот шаг и добавляйте видео
   по прямой ссылке (поле «ссылка на видео» в админке).
3. **Правила Storage.** Storage → Rules → вставьте содержимое `storage.rules`
   из этой папки → Publish. Загружать могут только админы, смотреть — все.
4. Готово: `admin.html` → вкладка «Видео» → выберите файл (MP4/WebM, до 80 МБ,
   лучше вертикальное 9:16) → «Добавить видео на главную».

Как это работает на сайте: первым идёт основное видео, дальше — добавленные
вами по порядку. Когда видео заканчивается, карусель сама переходит к
следующему (после последнего — возвращается к первому). Есть стрелки,
точки и свайп; соседние видео видны по бокам размытыми.

## Обновление v10: кабинет учителя, доска, рефералы — ОБЯЗАТЕЛЬНО обновить правила

**Без этого шага группы, оценки, посещаемость, доска и рефералы выдадут
«Missing or insufficient permissions».** Firestore Database → Rules → вставьте
весь файл `firestore.rules` из этой папки → Publish. Новые блоки:
`groups`, `attendance`, `grades`, `lessonBoards` (доска) и `referrals`.

Что важно знать:
- **Роль «Преподаватель» теперь выдаёт только админ.** Раньше ученик технически мог
  сам записать себе `role: teacher` в свой профиль; теперь правило `users` запрещает
  менять собственную роль. Назначать — админ-панель → «Ученики» → Роль.
- **Кабинет учителя** (роль «Преподаватель» → `dashboard.html`): группы, ученики
  (добавляются по никнейму — ученик должен быть зарегистрирован), посещаемость,
  оценки 0–10, плюс прежняя вкладка «Уроки по расписанию».
- **Доска на уроке** (`video-lesson.html`): видят все; писать может только учитель,
  открывший доску, и те, кому он включил переключатель (или «Разрешить всем»).
  Права проверяются правилами Firestore, а не только кнопками. Дать доступ можно только
  тем, кто вошёл в аккаунт (гости доску видят, но писать не могут).
- **Посещаемость в уроке группы:** у группы есть своя комната (кнопка «Войти на урок
  группы»). Учитель в ней видит список учеников, отметки «в комнате» и сохраняет
  посещаемость прямо из урока.
- **Новые ученики и никнеймы:** теперь в `nicknames/<ник>` сохраняется имя
  (`displayName`: «Азиза К.»), чтобы учитель видел имя, а не только никнейм.
  У учеников, зарегистрированных раньше, в списке группы будет только @никнейм.
- **Рефералы.** Код приглашения — никнейм ученика, ссылка `index.html?ref=никнейм`.
  Друг регистрируется → в админке «Рефералы» появляется запись «Зарегистрировался»
  (другу −10% на первый месяц). Друг оплатил → нажмите «Друг оплатил»
  (пригласившему −20% на следующий месяц) → после применения скидки — «Скидка применена».
  Ученик видит статусы своих друзей в кабинете. Суммы скидок — текстом в
  `dashboard-student.js`, `translations.js` и `admin.html`, если захотите изменить.

## v15 — собственный видеоурок (как Zoom)
- Видеоурок теперь идёт через **встроенный звонок** (`lesson-call.js`, `call-config.js`): сетка участников, микрофон/камера, показ экрана, «поднять руку», чат, список участников, у преподавателя — «выключить всем микрофон», «выкл. микрофон» и «удалить» для каждого. Jitsi остаётся запасным режимом (кнопка «Запасной режим (Jitsi)» или `?mode=jitsi`).
- **Опубликуйте правила Firestore заново** (`firebase-backend/firestore.rules`) — добавлена коллекция `lessonCalls` (peers / signals / chat). Без неё звонок не соединится.
- Видео идёт напрямую между браузерами (WebRTC), Firestore передаёт только «рукопожатие». Комфортно до ~6 человек. Для надёжности в строгих сетях добавьте TURN-сервер в `call-config.js` (инструкция в файле).
- Войти в звонок можно только из аккаунта; без аккаунта — запасной режим.
- Служебные документы `lessonCalls/*/signals` удаляются сами; старые `peers` можно чистить раз в месяц в консоли.
